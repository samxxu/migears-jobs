# P3-3 — isRunning() on Windows interpolates $pid directly into the exec() …

## Finding / 问题

- EN: isRunning() on Windows interpolates $pid directly into the exec() command string; while $pid is typed as int and thus safe from injection, it deviates from the module's otherwise careful escaping pattern.
- 中文: Windows 下 isRunning() 将 $pid 直接拼入 exec() 命令字符串；虽然 $pid 是 int 类型不会注入，但与模块其他位置谨慎的转义风格不一致。
- Where / 位置: `src/BackgroundJob.php:143`
- Verification / 验证: static / 仅静态推断

## Thread

- 2026-09-28 · `reviewer — migears-full-review` · `open` — filed from the 5th round.
- 2026-10-01 · `owner — migears-jobs` · `rejected` — the interpolation is real, but it is neither a deviation nor a defect. `isRunning(int $pid)` types `$pid` as `int` (`src/BackgroundJob.php:93`), and the Unix branch interpolates it just as bare — `exec('ps -p ' . $pid . ' -o stat= 2>/dev/null', $statOut, $statRc)` at `src/BackgroundJob.php:115` — so the two branches inside `isRunning()` are consistent with each other and there is nothing to bring into line. The module's `escapeshellarg` pattern targets string inputs that can carry shell metacharacters (`$command`, `$logFile`, `$workingDir`; README Security Notes); an `int` is not such an input.
- Probe (macOS, PHP 8.5.10; temp dir outside the repo, loaded through the module's own `vendor/autoload.php`): reflection reports `param pid type=int`; calling `isRunning()` from a file **without** `strict_types` with `'1; echo pwned'`, `'$(id)'` or `'1 2 3'` throws `TypeError`, and only a pure numeric string (`'123'`) coerces — to an `int` that cannot carry a metacharacter. No injection path exists.
- Escaping would be a regression, not a fix: `escapeshellarg((string) $pid)` wraps the number in quotes (`'123'` on Unix, `"123"` on Windows), turning the Windows filter into `PID eq '123'` and putting the `tasklist` match at risk. The bare form is the correct one here.
- Grade: this does not meet P3 — P3 is metadata and documentation drift, and nothing here is stale or contradicts the code; it is a style observation on code whose safety is argued above, so it is a false positive and no source change is made. Note the cited `:143` is now `tasklistHasPid()`; the `exec()` the finding means is `src/BackgroundJob.php:107`.
- 中文：`rejected`——插值属实，但既非偏离也非缺陷。`isRunning(int $pid)` 把 `$pid` 声明为 `int`（`src/BackgroundJob.php:93`），Unix 分支同样裸插值——`src/BackgroundJob.php:115` 的 `exec('ps -p ' . $pid . ' -o stat= 2>/dev/null', $statOut, $statRc)`——因此 `isRunning()` 内两个分支彼此一致，没有需要拉齐之处。模块的 `escapeshellarg` 模式针对的是可能携带 shell 元字符的字符串入参（`$command`、`$logFile`、`$workingDir`，见 README 安全注意）；`int` 不是这种入参。
- 探针（macOS，PHP 8.5.10；仓库之外的临时目录，经模块自带的 `vendor/autoload.php` 加载）：反射报 `param pid type=int`；在**未**声明 `strict_types` 的文件里调用 `isRunning()`，传 `'1; echo pwned'`、`'$(id)'`、`'1 2 3'` 均抛 `TypeError`，只有纯数字串（`'123'`）会被强制转换——转成一个不可能携带元字符的 `int`。不存在注入路径。
- 转义会是回退而非修复：`escapeshellarg((string) $pid)` 会给数字加上引号（Unix 下 `'123'`，Windows 下 `"123"`），把 Windows 过滤器变成 `PID eq '123'`，从而使 `tasklist` 匹配存在失配风险。此处裸插值才是正确写法。
