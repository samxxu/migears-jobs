### P2-3

- **Status / 状态**: Open
- **Where / 位置**: `src/BackgroundJob.php:56`
- **Verification / 验证**: reproduced (shell semantics)
- **EN**: A command ending in `&` returns the PID of the bare redirect subshell: in `nohup sleep 1 & > /dev/null 2>&1 & echo $!` the `$!` points at the second background job, which exits instantly, and the real command was neither nohup'd nor redirected, so `isRunning(thatPid)` is immediately false; a command containing its own `&` also only gets `logFile` applied to its last segment
- **中文**: 命令以 `&` 结尾时返回的是「空重定向子壳」的 PID：`nohup sleep 1 & > /dev/null 2>&1 & echo $!` 中 `$!` 指向瞬间退出的第二个后台作业，真实命令既没被 nohup 也没被重定向，`isRunning(该PID)` 立刻为 false；命令自带 `&` 时 `logFile` 也只作用于末段

### P2-4

- **Status / 状态**: Open
- **Where / 位置**: `src/BackgroundJob.php:219-221,175,98,106`
- **Verification / 验证**: reproduced
- **EN**: `pclose(popen(...))`'s return value is unchecked, so a failed `popen` makes `pclose(false)` throw `TypeError`; `getcwd()` can return false and is passed straight to `proc_open` (`TypeError: Argument #4 ($cwd) must be of type ?string, false given`); and `isRunning()` hard-depends on `exec()`, so a host that disables it raises a fatal `Error` instead of returning false
- **中文**: `pclose(popen(...))` 返回值未检查，`popen` 失败时 `pclose(false)` 直接 `TypeError`；`getcwd()` 可能返回 false 被直传 `proc_open`（实测 `TypeError: Argument #4 ($cwd) must be of type ?string, false given`）；`isRunning()` 硬依赖 `exec()`，在禁用 exec 的托管环境会抛致命 `Error` 而非返回 false
